The generated `.repo-map` artifacts are persisted in Turso rather than relying
on a local filesystem. Each repository revision creates a versioned snapshot in
`repo_map_snapshot`, individual artifact documents in `repo_map_artifact`, and
normalized ORM/database edges in `repo_relationship`.

Implemented semantic architecture stage:
Index source/schema -> Repo Context Architect (read-only LLM) -> save snapshot
-> Specification -> UI/UX + Backend -> Frontend -> Tester.
The bounded LLM summary is included in every development agent's context and in
architecture.md. Extracted relationship edges retain their evidence/confidence;
the LLM does not overwrite them. No configured source skips the LLM stage.
The Repo Context UI panel shows live full-run indexing/summarizing/saving status,
semantic summary, indexing counts/limits, stored artifact previews/downloads,
and relationship edges. Saved runs retain their exact snapshot identifier in
a repo_context prompt_output row; standalone reruns version this report too.
The five development prompts remain editable; the read-only context agent has
a fixed analysis policy in team_agents/repo_context.py.

Project context reuse:
Check saved snapshot + current GitHub commit + source/analysis configuration.
Unchanged context -> restore indexed records/semantic summary from Turso; no
file downloads, re-indexing, schema reflection, or architecture LLM requests.
Changed commit/configuration or explicit refresh -> build a new snapshot.
Live database metadata expires one hour after snapshot creation, independently
of GitHub. Cache hits do not extend that expiry. Source reads are pinned to the
checked commit SHA, and GitHub access errors never silently use a stale cache.
Cache signatures/version live in context_json, so no new SQL columns are needed.
Refresh Repo Context runs just the context stage, without a requirement or the
development agents. The panel displays Reused/Rebuilt, reason, and cache age/expiry.

Relationship inference should connect SQLAlchemy, JPA, and Prisma models to
database tables, SQL foreign keys to referenced tables, and ORM relation fields
to their related models. Every edge stores its type, confidence, and evidence
so agents can distinguish deterministic schema facts from inferred mappings.

Optional live database context:
GitHub source index + PostgreSQL/MySQL/SQL Server schema + Turso schema
                         ↓
               merged context and relationships
                         ↓
        Turso snapshot artifacts, including database-schema.json

Projects can enable a server database, Turso, or both. Connection configuration
references credentials by server environment variable name. The schema readers
inspect tables/views, columns, primary keys, foreign keys, and indexes; they do
not read application rows. Agent Team's Turso storage connection remains
separate from the optional database context sources.
